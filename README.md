# ALIREZArely

گیت‌وی فوق‌سبک VLESS برای دیپلوی روی Railway.

هیچ وابستگی خارجی ندارد — فقط کتابخانه استاندارد پایتون. بدون داشبورد، بدون رمز ورود، بدون UI.
فقط یک متن ساده مثل فایل‌های raw گیت‌هاب که لینک‌ها را می‌دهد.

## چه می‌کند

- اتصال‌های VLESS روی **WebSocket** را قبول می‌کند (لینک پورت 443 با TLS از طریق دامنه Railway)
- اتصال‌های VLESS خام **TCP** را هم قبول می‌کند (آدرس TCP Proxy به‌صورت خودکار از متغیرهای Railway خوانده می‌شود)
- `GET /` و `GET /sub` فقط دو تا لینک ساده برمی‌گرداند — بدون هیچ لاگین یا توکنی:

```
https://<domain>/sub
```

## ساختار فایل‌ها

| فایل | وظیفه |
|---|---|
| `main.py` | نقطه شروع: شنود پورت‌ها و تشخیص پروتکل (HTTP یا VLESS خام) |
| `vless.py` | هندلر پروتکل VLESS (TCP و UDP) |
| `httpd.py` | سرور HTTP مینیمال و ساخت لینک‌ها |
| `ws.py` | وب‌سوکت مینیمال بدون هیچ کتابخانه‌ای |

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `UUID` | ساخته می‌شود | **حتماً ست کنید**، وگرنه بعد از هر دیپلوی UUID عوض می‌شود |
| `PORT` | `8080` | پورت اصلی — Railway خودش ست می‌کند |
| `TCP_PORT` | `9443` | پورت شنود VLESS-TCP خام داخل کانتینر |
| `DOMAIN` | — | دامنه عمومی؛ خالی باشد از Host خود ریکوئست پر می‌شود |
| `TCP_DOMAIN` | خودکار | فقط برای بازنویسی دستی؛ پیش‌فرض از `RAILWAY_TCP_PROXY_DOMAIN` خوانده می‌شود |
| `TCP_PUBLIC_PORT` | خودکار | فقط برای بازنویسی دستی؛ پیش‌فرض از `RAILWAY_TCP_PROXY_PORT` خوانده می‌شود |
| `TAG` | `ALIREZArely` | اسم کانفیگ داخل لینک |
| `WS_PATH` | `/ws` | مسیر WebSocket داخل لینک |
| `DATA_DIR` | `/data` | مسیر ذخیره UUID |

نکته: روی Railway اگر متغیر `RAILWAY_ENVIRONMENT` وجود داشته باشد، برنامه روی چند پورت همزمان listen می‌کند
(`PORT` + `8080` + `443` + `TCP_PORT`) تا هم دامنه عمومی و هم TCP Proxyها همیشه به برنامه برسند —
فرقی نمی‌کند Railway پورت را چه مقداری inject کند.

## دیپلوی روی Railway

1. این ریپو را Fork کنید و روی Railway از روی آن دیپلوی کنید.
2. متغیر `UUID` را ست کنید (یا یک Volume به مسیر `/data` وصل کنید).
3. لینک‌ها: `https://<domain>/sub`
4. برای لینک TCP: در تنظیمات سرویس یک **TCP Proxy** بسازید — Railway متغیرهای
   `RAILWAY_TCP_PROXY_DOMAIN` و `RAILWAY_TCP_PROXY_PORT` را خودش ست می‌کند و برنامه
   آن‌ها را به‌صورت خودکار داخل لینک قرار می‌دهد (نیازی به تنظیم دستی نیست).

## تست محلی

```bash
UUID=11111111-2222-3333-4444-555555555555 python main.py
curl http://127.0.0.1:8080/sub
```

دو لینک برمی‌گرداند: یکی WS روی همان پورت، دیگری TCP خام روی 9443.
